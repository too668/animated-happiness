API 文档

YOO 图床 API。以下每个示例都是实测跑通的，不是设想。

为什么上传有两条路

文件要存进 Blob 存储，有两条路，区别在于字节是否经过边缘函数。

  • 压缩中转 —— 浏览器把文件交给边缘函数，函数再写库。边缘函数的请求体上限是 1MB，所以这条路只收图片，且前端会把超过 950KB 的图先压到限内。胜在一条 curl 就能传。
  • 原图直传 —— 函数只签发一个几十字节的临时 PUT 地址，浏览器拿它把字节直接写进存储。字节不路过函数，所以 1MB 这个上限根本不会被触发：任意格式、不压缩、单个文件可到 20MB（存储单值上限 25MB）。

注：1MB 只限制「进来的请求体」。往外发图片的响应体没有这个限制——实测 2.39MB 原图经 /i/ 返回是逐字节完整的，所以大图能正常显示。

POST /api/upload-url 大文件 · 原图

直传第一步：索取签名地址

curl -X POST "https://yooy.cc.cd/api/upload-url" \
  -H "Content-Type: application/json" \
  -d '{"filename":"photo.heic","size":3780000,"contentType":"image/heic"}'

响应

{
  "ok": true,
  "key": "2026/08/a09ed68c894c-photo.heic",
  "url": "https://yooy.cc.cd/i/2026/08/a09ed68c894c-photo.heic",
  "uploadUrl": "https://…edgeone.site/…/yoo-images/2026/08/…?q-signature=…",
  "expiresAt": 1788076565,
  "contentType": "image/heic",
  "method": "PUT"
}

直传第二步：把字节 PUT 给 uploadUrl

curl -X PUT "<上一步返回的 uploadUrl>" \
  -H "Content-Type: image/heic" \
  --data-binary @photo.heic
# → HTTP 200，文件已在存储里，url 立即可用

签名地址绑死了 PUT 方法、这个 key、600 秒有效期、以及 Content-Type——四样任何一样对不上，写入都不会成功，存储里也不会留下半个对象（GET /api/meta 仍报 404）。

但别指望能读到一个干净的 403。实测：拿 uploadUrl 去 GET 会正常返回 403 SignatureDoesNotMatch；而任何被拒的写（Content-Type 不符、方法不是 PUT、签名被改）都会被存储网关直接掐断连接——HTTP/2 下表现为 stream INTERNAL_ERROR，curl 记成状态码 000，浏览器里就是一个 Failed to fetch。所以自行接入时，第二步的 Content-Type 必须原样回传第一步响应里的 contentType（不是你自己猜的 file.type），并在客户端把「连接被重置」也当成上传失败来处理、必要时重新签发地址。url 在 PUT 成功前就已返回，但那时访问会 404。

PUT /api/upload ≤950KB · 仅图片

中转：原始字节（推荐）

curl -X PUT "https://yooy.cc.cd/api/upload?name=demo.png" \
  -H "Content-Type: image/png" \
  --data-binary @demo.png

中转：multipart（习惯用法也支持）

curl -X POST "https://yooy.cc.cd/api/upload" -F "file=@demo.png;type=image/png"

响应（两种方式一致）

{
  "ok": true,
  "key": "2026/08/6f20444f3562-demo.png",
  "url": "https://yooy.cc.cd/i/2026/08/6f20444f3562-demo.png",
  "size": 70,
  "contentType": "image/png",
  "name": "6f20444f3562-demo.png"
}

可接受 png jpg jpeg gif webp svg avif bmp。超 950KB 返回 413 并提示改用直传。文件名里的日期与随机前缀由服务端生成，原始名会 slugify 后留在 key 尾部便于识别。

GET /i/<key> 这就是图片链接

接口说明

Blob 存储不存在任何公开读取地址——官方 API 里没有 getDownloadUrl 之类的方法，签好的上传地址又只能 PUT，拿来读会 403。所以图片必须由这个路由把字节读出来再吐回去。你要复制去分享的链接就是它。 

curl -I "https://yooy.cc.cd/i/2026/08/6f20444f3562-demo.png"
# HTTP 200 · Content-Type: image/png · Cache-Control: public, max-age=3600
  • Content-Type 按 key 的扩展名推导；扩展名不在图片清单里会以 application/octet-stream 强制下载，避免这个域名被拿来执行上传的 HTML
  • ?download=1 可让图片也变成下载
  • 文件名含随机前缀，换图必换链接
  • 删除不会让链接立刻消失：原件当场就没，但边缘节点上那份缓存最多还会被命中一小时（max-age=3600），之后回源拿到 404。官方文档确认平台没有「从函数内部刷新指定 URL 边缘缓存」的能力，所以 max-age 就是删除延迟本身——这个值故意只给 1 小时。曾经打了一年（还带 immutable），结果删掉的图能续命一年
GET /api/list 可选分页

接口说明

获取所有图片列表，支持分页参数。

请求参数

参数类型默认值说明
limitnumber100本页数量，最大 500
cursorstring-上一页返回的 nextCursor
detail1-逐项补读元信息，得到真实 size 与 contentType（最多前 50 项，较慢）
all1-不限数量，由 SDK 自动聚合所有页

示例请求

curl "https://yooy.cc.cd/api/list?limit=20"

响应体

{
  "ok": true,
  "items": [
    {
      "key": "2026/08/6f20444f3562-demo.png",
      "name": "6f20444f3562-demo.png",
      "url": "https://yooy.cc.cd/i/2026/08/6f20444f3562-demo.png",
      "type": "image/png",
      "etag": "\"2cd8bde463f5d82aae0f0cec061d6b8f\""
    }
  ],
  "total": 1,
  "nextCursor": null,
  "hasMore": false
}

存储层的列表接口只返回 key 和 etag，没有文件大小这个字段，所以默认响应不含 size；要大小请加 detail=1。另外该接口必须显式带 paginate:false 才会返回 cursor——不传时 SDK 会自动聚合全部页且 cursor 恒为空，分页就变成了假的。

GET /api/meta

接口说明

读取单个对象的存储元信息（实测返回 content-type、content-length、etag、cache-control 等）。

curl "https://yooy.cc.cd/api/meta?key=2026/08/6f20444f3562-demo.png"
curl "https://yooy.cc.cd/api/meta?url=https://yooy.cc.cd/i/2026/08/6f20444f3562-demo.png"
GET /api/health

接口说明

报告存储桶是否真的可达，以及三条路径各自的体积上限。部署后先打这个，能立刻区分「代码没上线」和「存储不通」。

curl "https://yooy.cc.cd/api/health"
# {"ok":true,"store":"yoo-images","storage":{"ok":true,"sampled":0},
#  "limits":{"relayMaxBytes":972800,"directMaxBytes":20971520,"uploadUrlTtl":600}}
DELETE /api/delete 危险操作

接口说明

删除对象。可以用 key，也可以直接粘 /i/ 完整链接给 url（实测两种都通）。

请求参数

参数类型必填说明
keystring二选一形如 2026/08/6f20444f3562-demo.png
urlstring二选一图片完整链接，服务端会反解出 key

示例请求

curl -X DELETE "https://yooy.cc.cd/api/delete?key=2026/08/6f20444f3562-demo.png"
curl -X DELETE "https://yooy.cc.cd/api/delete?url=https%3A%2F%2Fyooy.cc.cd%2Fi%2F2026%2F08%2F6f20444f3562-demo.png"

响应体

{ "ok": true, "key": "2026/08/6f20444f3562-demo.png", "message": "已删除" }

删除前先查存在性，不存在返回 404 {"ok":false,"error":"文件不存在"}。注意存储方法叫 getMetadata()——这个 SDK 上没有 head()，早期版本调 store.head() 必定抛异常，被 catch 后当成「文件不存在」，导致删除功能对任何文件都返回 404、一张也删不掉。

注意事项

  • 体积上限：直传 20MB（任意格式）· 中转 950KB（仅图片）
  • 中转可接受 png / jpg / jpeg / gif / webp / svg / avif / bmp；GIF 与 SVG 前端不做压缩（会丢动画或栅格化），超限请直接走直传
  • 图片链接的 Content-Type 由 /i/ 路由按扩展名决定，与存储层记录的值无关——SDK 的 store.set() 并不接受 contentType 参数
  • 链接指向 /i/ 函数路由，不是静态文件；换图必须换链接，因为响应标了 immutable
  • 全部接口允许跨域，可被任意前端直接调用（自用，未加鉴权）
  • 删除不可撤销
  • 存储总量 1GB，单个对象 25MB（平台配额）
